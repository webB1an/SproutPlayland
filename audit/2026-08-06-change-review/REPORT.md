# 2026-08-06 代码改动与游戏体验审查

## 结论

本次改动明显提升了页面切换、卡片入场、首页横滑发现性、拼图托盘可读性和全游戏结算的一致性。整体已经从“若干小游戏拼在一起”向“同一套儿童游戏产品”靠近。

但当前不建议直接发布：拼图在两次完整组装后都没有进入完成流程；擦擦发现的浏览器预览拖拽也没有触发擦除。另有一个跨玩法的高影响内容问题：首关“小芽和太阳”不是恐龙，却被直接带入“恐龙配对/目标恐龙泡泡”等玩法，导致文案、目标和画面互相矛盾。

综合评分：

- UI 一致性：7/10
- 视觉吸引力：7/10
- 玩法清晰度：6/10
- 操作与反馈：6/10
- 完成感与继续动力：8/10（结算可正常触发的玩法）
- 发布就绪度：5/10

## 最高优先级问题

### P1 — 拼图完整组装后不结算

两次独立试玩中，4 块拼图都已视觉对齐，等待 5 秒并再次点击空白区域后仍没有庆祝或完成弹窗。第二次证据见 `25-puzzle-complete-retest.png` 和 `26-puzzle-after-blank-tap.png`。

风险集中在新的多指状态机：`PuzzleInteractionController.ts` 以触点 ID 查找会话，`finishDrag` 找不到会话时直接返回；结算又依赖 `settlePlacedPieces()` 或最后一次 `finishDrag`。建议加自动化用例覆盖单指拖完 4 块、多指打断、`TOUCH_CANCEL`、触点 ID 不一致，并在无法取得 session 时至少执行一次兜底结算检查。

### P1 — 擦擦发现未响应本次预览拖拽

在画板上完成 7 条横向拖拽后，云层与进度条均未变化，手势提示也仍在。证据见 `11-scratch-start.png` 与 `12-scratch-progress.png`。同一浏览器控制下拼图拖动和首页横滑均可工作，因此应优先复测事件是否被云朵子节点/遮罩截断，并在真机触摸上验证。

### P1 — 首关素材与“恐龙”玩法语义冲突

“小芽和太阳”作为第一个共享 artwork，被直接用于所有小游戏：

- 恐龙配对提示“把下面的恐龙…”，实际拖的是整张岛屿场景；
- 泡泡提示“目标恐龙”，目标却是“小芽和太阳”；
- 翻牌则把“场景”和恐龙并列为同一类卡片。

证据见 `14-shadow-start.png`、`17-bubble-start.png`、`23-memory-feedback.png`。建议给共享素材增加玩法标签，例如 `subjects: ['dinosaur']` / `sceneOnly: true`，各玩法按语义筛选，不要只复用同一数组。

## 代码审查发现

### P2 — UI token 目前只统一了 RGB 转换，没有真正统一视觉参数

新增 `UiTheme.ts` 定义了颜色、圆角、字号、阴影 token，但业务页面只使用了 `toColor()`；`UI_COLORS`、`UI_RADIUS`、`UI_FONT`、`UI_SHADOW` 没有任何调用。当前各页仍大量硬编码尺寸和颜色，所以“建立主题文件”尚未转化为实际一致性保障。

建议先迁移最常重复的四类组件：页标题、难度胶囊、关卡卡片、完成弹窗，再禁止新增同类魔法数字。

### P2 — 错误泡泡的蓝色扩散圈语义容易被理解成“选中了/答对了”

错误点击后，蓝色描边扩大并突出错误泡泡，颜色与本玩法主色及正常选中态接近。证据见 `18-bubble-wrong.png`。对于 2～5 岁儿童，更合适的是让错误泡泡轻轻回弹，同时短暂脉冲左侧目标卡或正确泡泡；避免把注意力继续锁在错误对象上。

### P2 — 翻牌卡背按位置交替粉/紫，产生虚假的配对线索

`MemoryGamePage.ts` 以 `index % 2` 决定卡背颜色。证据见 `22-memory-start.png`。孩子可能推断“同色卡背是一对”或“异色卡背是一对”，这与真正的记忆规则无关。建议同一局使用统一卡背，只用翻开内容表达配对关系。

### P3 — 格式与可维护性小问题

- `MiniGameShared.ts` 文件末尾多一个空行，`git diff --check` 报警。
- `tsc --noEmit` 受全局 TypeScript 6 的 `moduleResolution=node10` 弃用检查阻断；加 `--ignoreDeprecations 6.0` 后项目通过。建议将项目检查固定到 Cocos 支持的 TypeScript 版本，避免环境漂移。

## 体验亮点

1. 首页：健康。分页点、末端吸附和首次轻推有效解决“第五个玩法藏在右侧”的问题；横滑后最后一张卡能完整显示。
2. 选关：健康。四个小游戏统一了标题、难度胶囊、卡片结构和主题配色，错峰入场让页面更有生气。
3. 拼图设置：健康。4/9/16 块与轮廓按钮图形化，中心预览明确；但按钮的高光 3D 风格与首页扁平插画仍有风格差。
4. 拼图操作：部分健康。托盘间距比旧逻辑更清楚，4 块不会互相遮挡，吸附位置也容易理解；结算回归是阻断项。
5. 擦擦发现：异常。云朵画面柔和，但规则呈现像规则网格覆盖层，神秘感有限；本次预览无法擦除。
6. 恐龙配对：部分健康。上下结构和箭头让操作方向很明确，完成弹窗正常；首关整图对整图几乎没有识别挑战，吸引力偏弱。
7. 泡泡找找：健康但可优化。目标卡、漂浮泡泡、连续回合节奏清楚，点击命中感好；错误反馈语义与首关素材需要修正。
8. 恐龙翻翻：健康。翻牌速度、错误停留时间、配对后的星光和结算节奏都合适；卡背颜色应统一。
9. 完成弹窗：健康。全玩法共用星星、勾选、重玩/下一关/菜单，下一关轻脉冲能明确引导继续，是本次改动最成功的统一点。

## UI 一致性与吸引力判断

一致性提升主要来自结构和动效，而不是完整视觉系统。页面背景、卡片布局、返回按钮和结算逻辑已经统一；但首页的柔和扁平图标、拼图设置/结算的高光 3D 按钮、游戏内程序化几何图形仍像三套美术语言。

吸引力方面，恐龙插画本身色彩友好、识别度高，微动效也增加了生命感。最弱的是首关整景素材进入配对/泡泡后目标过于显然、语义又不匹配；它更像“教学占位关”，而不是能让孩子产生再玩一次欲望的正式关卡。

## 无障碍与证据边界

游戏全部渲染在 Canvas 内，DOM 中没有可读的游戏按钮或结构；本次只能确认视觉和触控体验，无法从截图证明屏幕阅读器、键盘焦点、读序或 WCAG 符合性。代码交互以 `TOUCH_*` 为主，也未观察到键盘替代路径。目标用户以触屏儿童为主，但仍建议为家长设置、返回和暂停等外围控制提供可访问语义，并实测色弱、低视力和减少动态效果场景。

## 建议实施顺序

1. 修复并回归拼图结算、擦除触控两个阻断问题。
2. 为 artwork 增加语义标签，先把“小芽和太阳”从“目标恐龙”类玩法中排除或改文案。
3. 将错误反馈改为“弱化错误对象、强化正确目标”。
4. 统一翻牌卡背颜色。
5. 真正迁移 UI token，优先统一标题、胶囊、卡片和按钮。
6. 最后再做动效细节和高/中/低难度的节奏打磨。
