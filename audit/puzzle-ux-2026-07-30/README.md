# 拼图游戏体验审查

审查范围：首页进入拼图、拼图列表、难度与形状选择、拖拽和吸附过程。

## 结论

当前核心玩法已经成立，插画、卡片与拖拽反馈也适合低龄儿童。最需要优化的不是继续增加装饰，而是让“下一步该点哪里”和“拼块该放哪里”更加直觉。

## 流程

1. 首页：健康。三个游戏入口清楚，第一个拼图图标容易识别。
2. 拼图列表：一般。插画丰富，但 12 张卡片同时出现导致单张图片偏小，横向滑动也缺少视觉提示。
3. 难度与形状选择：需优先优化。必须分别选择左、右选项后开始按钮才出现，没有默认选项，首次使用容易停顿。
4. 拼图过程：一般。拿起、移动、吸附反馈已具备，但橙色空槽过强、缺少淡化原图或位置提示；拼块重叠时底层拼块较难拿到。
5. 完成反馈：未在本次截图操作中完整验证。代码中已有星星与完成弹窗，但按钮依赖文字，不符合“儿童看图操作”的方向。

## 优先级建议

### P0

- 默认选中 4 块和标准拼图形状，让绿色开始按钮进入页面时就出现。
- 难度不要继续用星星表达，改成清晰的 2×2、3×3、4×4 拼块图；星星只用于完成奖励。
- 给拼图底板增加 10%–18% 透明度的完整原图，点击问号时短暂提高到 35%–45%。
- 为拿起、正确吸附、完成增加不同声音；低龄儿童主要依赖声音确认操作结果。

### P1

- 拼图列表改为每屏重点展示 6–8 张较大的卡片，右侧露出下一张卡片或增加分页圆点，提示可以左右滑动。
- 拼块堆叠区减少重叠；错误落下后若覆盖其他拼块，轻微错开，避免底层拼块无法点击。
- 完成弹窗使用“重玩”“下一张”“返回列表”三个大图标，文字只作为辅助。
- 正确吸附时增加短促缩放、光圈和轻音效，完成时增加星星飞入列表的动画。

### P2

- 为尚未获得和已获得的星星增加形状差异，不只依赖紫色/黄色。
- 记住上一次难度和形状，但首次进入仍使用最简单配置。
- 增大返回、帮助按钮的有效点击区域，并验证刘海屏安全区。

## 证据限制

- 本次使用 Cocos Web 预览的横屏 iPhone 14 Pro 模拟尺寸。
- Canvas 页面没有可读的语义结构，因此无法从截图确认键盘、读屏标签和真实设备触觉反馈。
- 本次没有稳定触发最后一块的完成弹窗，所以完成反馈同时参考了当前实现代码。
